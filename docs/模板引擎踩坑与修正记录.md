# 论文格式医生 · 模板驱动引擎「踩坑与修正」记录

> 用途：这份手册把国内版（导师版 tfd-mentor / 学生版 tfd-desktop）在 2026-09 这一轮发版里
> 踩过的所有坑、以及对应的修法，**系统记下来**，供下一步「海外版 DocxFmt」的模板引擎
> 优化直接复用——**同样类型的坑，以后不能再踩**。
>
> 适用范围：任何「按学校/单位模板画像驱动、批量改写 Word 标题/正文样式」的 OOXML 引擎。
> 海外版的 5 通道模板引擎若引入「按模板套标题样式」，下面每一条都是必踩点，请提前规避。

---

## 坑 0（最根本的设计铁律）：模板画像只驱动格式值，绝不准写死

- **现象**：早期版本把某些学校的具体格式值（字体/字号/页边距）硬编码进代码或文案。
- **修法 / 铁律**：一切格式要求从用户提供的模板画像（profile）提取，优先级
  `模板批注 > 样式定义 > 通用规范`，通用规范仅兜底且必须明确提示客户。
- **海外版注意**：APA/MLA/Chicago/IEEE/Harvard 这些「国际格式」本身也是「规范」，不是写死值；
  同样要走 profile / 规范层驱动，别把 `Times New Roman 12pt` 之类写进代码常量。

---

## 坑 1：套标题样式时写了「文档里不存在的 styleId」→ 标题看着像无样式 + 第二遍重标（非幂等）

- **版本**：导师版 v1.1.23→v1.1.24 / 学生版 v1.3.128→v1.3.129（本轮最大 bug）
- **根因（决定性复现）**：
  - 模板画像里的标题 styleId（如山大模板真实的 `00001d / 000022 / 000010`）来自**模板文档**的样式表；
  - 但学生稿自己用的是另一套 styleId（`3`=heading 1 / `4`=heading 2 / `2`=heading 3）；
  - 引擎把画像的 styleId 直接写进 `w:pStyle/@w:val`，**不校验该 id 在学生稿里是否存在**；
  - 结果写进去的是「孤儿 id」→ Word 打开时按 Normal 渲染，标题**看着像「无样式」**；
  - 下一遍 `cur(孤儿id) ≠ target` 必然重新标注 → 一/二级标题非幂等（三级恰好命中反而没事）。
- **修法**：新增 `_resolve_heading_style(target, styles_map, lvl)`，套样式前把画像 id 解析成
  **文档里真实存在**的标题样式：
  1. 画像 id 已在目标文档样式表 → 直接用（最常见，不动它）；
  2. 不在 → 按级别名匹配文档原生标题样式（`name` 含 `heading N` / `标题 N` / `N级标题`，
     排除 `toc`/`目录`）→ 复用学生稿自己的 `3/4/2`；
  3. 仍解析不出 → 退回原 target（不崩）。
  **关键不变量**：`apply`（写样式）与 `needs_fix`（判是否需改）必须走**同一个**解析结果 →
  第一遍写入的 id == 第二遍判等用的 id → 幂等。
- **验证**：真实山大 styleId 画像跑张倩倩原稿 → 第一遍一/二级套上真实 `3/4`，第二遍=0、第三遍=0。
- **海外版必踩点**：只要海外版做「按模板把标题套成某个 styleId」，就一定遇到
  「模板 styleId ≠ 用户文档 styleId」。请**从第一天**就做 styleId 存在性校验 + 同名回退，
  别等上线后被「第二遍重标」投诉才补。

## 坑 2：真实目录（TOC 域）段落被误改格式/加批注

- **版本**：v1.1.21 / v1.3.126 区间
- **根因**：Word 自动生成的目录条目是 `HYPERLINK _Toc…` / `PAGEREF _Toc…` 域段落，
  引擎的标题/正文修正主循环把它们当成普通段落去套格式、加批注。
- **修法**：正文循环加守卫 `_para_has_toc_field(p)` —— 段落内任一 run 含 TOC 域引用即 `continue` 跳过。
- **海外版注意**：目录/书签/交叉引用都是「域段落」，改写引擎一律要先识别 `HYPERLINK`/`PAGEREF`/
  `REF` 域再决定是否下手。

---

## 坑 3：结构页 pass 把「摘要I / ABSTRACTII」误判为摘要标题去套格式

- **版本**：v1.1.22→v1.1.23 / v1.3.127→v1.3.128
- **根因**：结构页套用 pass 的 `classify_structural_title` 把摘要页里带页码域的「摘要I」「ABSTRACTII」
  条目误判成「摘要标题」去套格式+加批注（它样式属目录样式或含 TOC 域）。
- **修法**：结构页 pass 的①主循环 classify 段 ②内容 sweep 段，均加
  `if _is_toc_style(_cur_style_id(p), styles_map) or _para_has_toc_field(p): continue`。
- **海外版注意**：封面/摘要/目录/参考文献/致谢/附录这些「结构页」要独立分区处理，
  且任何「看起来像标题但样式是 TOC/目录」的段落都必须先排除，再谈套格式。

## 坑 4：第二/三遍跑完，旧批注气泡被「带下来」显得脏

- **版本**：v1.1.21→v1.1.22 / v1.3.126→v1.3.127
- **根因**：旧版 `_apply_comments` 只追加不清旧，第二遍把第一遍的旧批注一并带下
  （新增 0 条但视觉上一堆旧气泡）。
- **修法**：`fix()` 开头按工具作者名清掉本工具上次写的批注（`_strip_our_comments`），
  保留用户/模板原有批注；`docxutils.ensure_comments_part` 优先读清理后的 comments.xml。
- **海外版注意**：任何「多遍可重入」的批注式修正，都必须在每遍开头清掉自己上一遍的产物，
  否则幂等性在「视觉层」永远不成立。

## 坑 5：两版（导师/学生）逻辑漂移，修 A 漏 B

- **版本**：全程
- **根因**：导师版与学生版是**两份独立仓库、同一套引擎代码复制维护**，改一处常忘同步另一处
  （如 `fix(..., author=None)` 签名、批注副本策略、TOC 守卫）。
- **修法**：铁律——凡动 `headings_fix.py`/`docxutils.py` 的引擎逻辑，**两仓同步改**；
  发版前跑两仓回归套件。
- **海外版注意**：如果海外版要「一份引擎多产品线」，请**从架构上**做成单仓/单包复用，
  别再复制两份——复制即漂移之源。

## 验证铁律（踩坑后立下的，海外版直接继承）

1. **真实文档两遍法**：任何「幂等/二次标注」类修复，必须用**真实学生论文原稿 + 真实学校模板画像**
   跑 `fix()→fix()` 两遍验证第二遍=0；合成样例永远复现不出这种 bug（已多次验证）。
2. **PII 安全**：真实论文只在 `D:\AgentSpace\_smoke\` 副本上操作，验证后即删含未脱敏论文的 `.docx`，
   绝不出本地盘、绝不进仓。
3. **发版实证三步**（防 Nuitka 静默丢资源）：①`gh release download` 解包列目录
   ②二进制 grep 品牌串（reedskill / hi@reedskill.com / 论文格式医生 / 芦苇不熬夜）
   ③SHA256+文件大小与 `gh api` 声明一致。
4. **本机真机秒退验**：安装包双击确认不秒退（rc=124 正常、秒退=P0），这步需用户在 Windows 本机做。

## 一句话总结给海外版

> 模板驱动引擎最大的两个隐形炸弹是 **「styleId 跨文档不存在」** 和 **「域段落/结构页被当正文改」**。
> 前者导致非幂等重标，后者导致目录被毁。两者都要在引擎设计第一天就内置
> 「styleId 存在性校验 + 同名回退」与「TOC/结构页预排除」，别等上线后救火。
