## 0. 为什么写这份文档

国内版「论文格式医生」迭代了上百个版本，踩了太多"边做边改、需求没钉死"的坑。

## 1. 产品定位与商业模式

### 1.1 定位
- **离线优先的论文 / 文档格式合规检查 + 一键修正桌面软件**。
- **核心卖点 = 隐私安全**：论文文档**绝不离开本机**；格式检查与修正**全部为本地确定性规则引擎，不调用任何云端大模型（LLM）**。
- 目标市场：欧美高校学生、科研人员（APA / MLA / Chicago / IEEE / Harvard 是海外最常用引用规范）。
- 与国内版关系：两者独立产品、独立代码库、独立授权。国内版是中文高校模板驱动；海外版是"内置通用规范 + 可选学校模板/LaTeX 模板对比"。

### 1.2 商业模式（模型 B —— 无水印）
这是**产品铁律**，代码必须与之一致：

| 能力 | 未激活用户 | 已激活用户 |
|---|---|---|
| **格式检查（check）** | **完全免费、不限次数、功能完整** | 同左 |
| **一键修正（fix）** | **第 1 次免费**；**第 2 次起需激活码** | **无限次** |
| **输出文档水印** | **无。任何时候都不向输出文档写入任何水印/试用标记** | 无 |
| **可用性** | 检查全程离线可用；修正首次试用后，再修正需联网校验授权 | 检查/修正引擎均离线；仅心跳/校验触网 |

设计要点：
- **不做 crippleware（残废版）**。海外用户对"产出物被打标"极度敏感，正式论文带水印观感差且伤害信任；故**彻底放弃水印防白嫖**，改用"中台登记试用额度 + 机器绑定"防重置。
- **付费即终身**（lifetime 码），不做订阅纠缠。
- 检查免费无限，是口碑入口；修正第 1 次免费，让用户拿自己论文验效果，第 2 次起转化。

## 2. 目标用户与典型场景

| 用户 | 场景 | 痛点 |
|---|---|---|
| 欧美研究生 | 学校给 Word 模板 + 要求用 APA | 模板页边距/字体 vs APA 引用格式两边都要满足，人工难查 |
| 本科生 | 教授只给了 PDF 格式指南 | 没有可机器读的模板，只能照着手抄格式 |
| 科研人员 | 投 IEEE 会议 | 会议模板（Word/LaTeX）与 IEEE 引用规范要同时合规 |

核心洞察（已用真实样本验证）：**页面排版归学校（页边距/字体/行距/对齐/缩进/标题层级），引用格式归规范（APA 等只管参考文献）**。二者是两条独立维度，海外版按此拆分。

## 3. 功能需求（FR）

### FR1 · 内置通用规范（必选其一）
- 内置 5 套规范写死在代码：**APA / MLA / Chicago / IEEE / Harvard**（`REFERENCE_STYLE_KEYS`）。
- 提供 **"Other"**：用户不按任何已知规范时，仅凭"学校模板 / 手填问卷 / LaTeX"也可检查。
- 规范 = "引用格式默认值" + 页面排版的**兜底参考值**（注意：**页面排版不是规范的要求**，见 FR4 裁决规则）。
- 规范值集中在 `engine/specs.py`，不依赖任何外部文件或网络。

### FR2 · 五输入通道，统一汇聚到 `TargetProfile`
用户**任选其一或组合**提供"目标格式要求"，全部映射到同一数据结构 `TargetProfile`：

1. **规范选择**（FR1）：选 APA 等 → 套用内置默认值（页面为软参考）。
2. **手填格式问卷**：软件内置问卷（页边距/字体/字号/行距/对齐/首行缩进/段后间距/标题层级/参考文献格式等），用户照学校要求手填。
3. **AI 填表配置导入（YAML/JSON）**：用户把学校要求丢给任意 AI，让 AI 按我们导出的 `ai_questionnaire_template.yaml` 填出 YAML（旧版 JSON 也兼容），软件直接吃。需兼容 AI 常见的 `filled:` / `data:` 等包装。
4. **学校模板上传（docx）**：上传学校 Word 模板 → 读其页面排版当"学校要求"。
5. **LaTeX 模板（.cls / .sty / .tex）**（第二轮新增）：解析 LaTeX 模板抽取页面排版与引用风格。

统一合并入口：`build_target(spec_key, template=, ai=, questionnaire=, latex=)`。
叠加优先级：`template > ai > questionnaire > latex`（页面以显式来源为准）；引用仅当显式来源提供才覆盖规范；来源间冲突记录进 `TargetProfile.conflicts`。

### FR3 · 文档检查（离线读 docx）
读取待检 `.docx`，提取**实测 profile**，至少覆盖以下维度：

- **页面**：上/下/左/右页边距（多分节取众数并标记不一致）、正文字体、字号、行距。
- **段落级排版**：正文对齐、正文首行缩进、段后间距、参考文献悬挂缩进。
- **结构**：标题层级使用情况、是否含参考文献段落及其条目。
- **采样范围**：正文字体/字号统计须**包含表格内文字**（论文三线表大量存在），不得只扫顶层段落。

读取的健壮性要求：
- 字体/字号/行距/对齐/缩进/段距均需**三级回退**：run → 段落样式 → 文档默认（Normal 样式）。
- 段落属性缺省语义须按 Word 规范补齐（如未显式设置对齐 → 视为左对齐；未设置缩进/段后间距 → 0），否则会产生大面积"未能读取"误报。
- 行距需正确区分**倍数制**与**固定值制（EXACTLY / AT_LEAST）**，固定值不得被误读为倍数。
- 损坏 / 非 docx / 加密文档须抛明确错误（`DocxReadError`），不得崩溃或静默。
- 参考文献段落识别须稳健（多语言标题变体、且需有"后随条目"佐证），避免正文中出现 "see References" 之类短句被误判。

### FR4 · 对比裁决报告
- 把"文档实测 profile"与"目标 `TargetProfile`"逐维度比对，每维度给出 `pass / warn / fail / info`，并**标注该结论来源（规范 / 学校模板 / 问卷 / AI / LaTeX）**。
- **裁决规则（核心）**：
  - **引用格式类（reference_*）**：始终**以规范为准，硬判**（除非用户/学校显式给出引用字段）。
  - **页面与段落排版类**：以**显式来源（学校模板 / 问卷 / AI / LaTeX）为准**；若只有规范兜底值，则该维度降级为 `info`，**不得强制 fail**。
- 当显式来源之间冲突（如学校模板左页边距 1.5″、问卷填 1″），报告中**高亮列出全部冲突项**，由用户裁决。
- 报告须说明：规范页维度仅作参考、引用始终以规范为准。

### FR5 · 一键修正（第二轮新增）
**产品铁律：只改格式，绝不改内容。**

- **允许改动的（纯格式层）**：
  - 页面：页边距、正文字体、字号、行距。
  - 段落：正文对齐、首行缩进、段后间距。
  - 参考文献：悬挂缩进、编号标记（顺序编码 vs 著者-出版年）——**只重排格式与既有条目的排版，绝不新增/删除/改写任何文献内容**。
- **绝不允许改动的（内容层）**：
  - 任何正文文字（包含表格、页眉页脚、脚注、文本框等处的文字）。
  - 段落的增删、图表、图片。
  - **标题段**：不得改动标题的字体/字号（否则 18pt 标题会被压成正文 12pt，视觉层级崩塌）。标题的对齐/缩进/行距/段距亦应保持不动。
- **输出**：永远写**新文件**，绝不覆盖原件；默认输出名 `原名_fixed.docx`，若已存在则自动加序号（`-2` / `-3`）**不得覆盖上一次的结果**。用户显式指定 `--out` 时以用户为准（但仍不得等于输入路径）。
- **预览模式**：`--preview` 只列出"实际会变"的项，格式为「现状 → 目标」（如 `上页边距：2.0″ → 1.0″`）；已经合规的项不得列出；预览**不落盘、不消耗试用次数**。
  - **产品决策（2026-09-11 拍板）**：预览**受门禁约束**（属付费价值的一部分，试用耗尽后不再提供）；而「已合规、无需修正」的判定**不受门禁约束、不消耗试用**——因为它不产生任何副作用，且与免费的 `check` 同级。若把它也挡在门禁后，会出现"文档本来不用改却被报成试用已用完、等于劝人白买码"。
  - **入参校验先于门禁（实现约束）**：输入文件是否存在、`--out` 是否指向原件、目标画像能否构建，都必须在授权裁决**之前**完成并返回各自的退出码（rc=2），不得把参数错误报成"试用已用完"（rc=3）。
- **可验证性**：必须有自动化断言保证"修正后全文文字逐字与修正前一致"（参考文献段的 `[n]` 前缀为唯一豁免，且须单独断言"仅新增前缀、其余字符序列完全一致"）。

### FR6 · 授权与门禁（第二轮新增）
- **检查（check）无门禁**，任何时候免费可用。
- **修正（fix）门禁**（见 1.2）：调用修正前先裁决；未激活且试用已用 → 拒绝并提示激活（CLI 退出码 3）。
- **防重置**：试用额度须同时**向中台登记**（机器指纹绑定），使用户卸载重装无法再次白嫖；本地状态也做机器绑定。
- **激活**：输入激活码 → 向中台验证 → 写入本地状态（含种类 kind，如 lifetime）。
- **中台复用**：复用既有 `tfd-auth` 中台（Cloudflare Workers + D1），海外版渠道 `channel = 'global'`；**密钥/Admin Key/Token 一律不进代码、不入仓、不入 memory**。
- **门禁一致性（重要）**：GUI 与 CLI 必须**共用同一门禁实现**，不得存在一个入口能绕过另一个入口的限制；预览/失败路径不得误计试用次数。

### FR7 · 输出与入口
- **GUI**（tkinter）：选规范 → 传模板（docx/LaTeX）/填问卷/导入 AI JSON → 选待检文档 → 运行体检 → 看报告 → 一键修正（带预览确认）。
- **CLI** 子命令：
  - `gui`：启动桌面 GUI。
  - `check 论文.docx --spec APA [--template ...] [--ai ...] [--questionnaire ...] [--latex ...] [--out ...] [--json]`。
  - `fix 论文.docx --spec APA [--out ...] [--preview] [--json]`。
  - `activate 激活码` / `status`：授权。
  - `export-schema out.json`：导出 AI 填表模板。
- **`--json` 约定**：输出结构化 JSON（含 meta / summary / resolution / conflicts / findings / profile）。**JSON 必须保证在任意终端（含 Windows GBK 中文控制台）下都是合法可解析的 UTF-8**，不得因终端编码被替换成 `?`。
- **终端健壮性**：中文 Windows 控制台默认 GBK，报告中含 ✅/❌ 等符号；进程不得因此抛 `UnicodeEncodeError`；管道/重定向场景输出应为 UTF-8。

### FR8 · 隐私与联网边界（须精确理解，勿混淆）
- **格式检查引擎（`src/engine/*`）与修正引擎（fixer）**：**零网络请求、零 LLM**。这是产品核心承诺，任何在引擎路径中触网都算违规。
- **授权模块（`src/license/license.py`）**：允许且仅允许在"激活 / 试用登记 / 心跳"时访问中台。这是唯一允许联网的模块。
- 离线宽限：中台不可达时不得阻断本地流程（除非服务器明确返回 revoked/expired）。

## 4. 非功能需求（NFR）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR1 | **离线安全** | 格式引擎（engine/ + fixer）零网络、零 LLM；**唯一例外是授权模块的激活/心跳**（见 FR8）。 |
| NFR2 | **确定性** | 格式判断来自规则引擎（阈值 + 枚举），不调大模型、无随机性。同文档同参数 → 同结果。 |
| NFR3 | **代码隔离** | 与国内版 `论文格式医生\` 完全隔离：不 import、不共享、独立 `.venv`、独立目录。 |
| NFR4 | **跨平台** | 纯 Python + tkinter，Windows / macOS / Linux 均可运行。 |
| NFR5 | **可维护** | 规范值集中在 `specs.py`；问卷字段集中在 `QUESTIONNAIRE_SCHEMA`（单一真相）；新增规范/字段只动一处。 |
| NFR6 | **内容零改动（修正）** | 修正前后文档**文字内容逐字一致**，须有自动化断言守护。 |

## 5. 数据模型 — `TargetProfile`（核心中间层，实际字段）

五通道统一汇聚于此，是海外版的数据骨架（`engine/questionnaire.py`）：

```pythonc
TargetProfile:
  source: str                    # "spec" 或 "spec+school+ai_import..." 组合标识
  spec_key: Optional[str]        # 内置规范 key（APA/MLA/...），非内置则 None
  page: dict                     # 仅含已显式设置的页面/段落级值，键见 PAGE_KEYS
  heading_levels: Optional[int]  # 标题层级数
  reference_style: Optional[str] # 引用规范标识
  reference_hanging_indent_in: Optional[float]  # 参考文献悬挂缩进（英寸）
  reference_numbered: Optional[bool]            # True=顺序编码（如 IEEE [1]）
  resolution: dict               # 维度 -> 来源标签（spec / school / user / ai_import / latex）
  conflicts: list                # 显式来源间冲突：[{"dim", "entries":[(label,val),...]}]
```

`PAGE_KEYS`（`page` 内允许的键，唯一来源）：
```
margin_top_in, margin_bottom_in, margin_left_in, margin_right_in,
font_family, font_size_pt, line_spacing,
body_alignment, first_line_indent_in, space_after_pt
```

字段字典（问卷 schema，驱动手填 UI、AI 填表 JSON 与报告维度标签）：
`QUESTIONNAIRE_SCHEMA` —— 每项含 `key / label / group / type / options / default / unit / help`。
`choice` 类型必须做白名单归一（大小写不敏感匹配；不在白名单则丢弃，**不得臆造值**）。

合并语义：`build_target()` 以规范为基线，依次叠加显式来源；`_overlay_one()` 登记冲突；`merge_school()` 为向后兼容的二元合并。

## 7. 验收标准（v2 当前状态）

- ✅ 合规 APA 文档 → 相关维度 pass。
- ✅ 偏离文档（页边距 0.5″、Calibri 10pt、单倍行距）→ 正确报 fail/warn。
- ✅ 学校模板左页边距 1.5″ 覆盖规范 1″ → 报告标"以学校为准"并列出冲突项。
- ✅ `export-schema` 能导出 AI 填表 JSON 模板。
- ✅ 引擎全程零网络、零 LLM；`--json` 在中文 Windows 终端下可被解析。
- ✅ 一键修正：生成新文件、正文逐字不变、标题不被压、默认不覆盖上次结果。
- ✅ 授权：修正第 1 次放行、第 2 次拒绝（rc=3）、`status` 可见试用状态。
- ✅ 全量 pytest 通过（当前 50 项），CLI 端到端 5 步通过。

## 8. 已知边界 / 不在当前范围

**明确的实现上限（有意为之，非缺陷）**：
- **LaTeX 解析不追求通吃**：不运行 TeX 引擎、不解析用户自定义宏/复杂命令；目标覆盖主流 ~80%（IEEEtran / apa6 / article+geometry / revtex / ACM 等），取不到的值回落规范并提示用户。
- **参考文献只做格式层**：不做逐条语义校验（作者/年份/DOI 是否真实、是否与正文引用对应），也不改写文献内容。
