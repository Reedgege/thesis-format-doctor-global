## 1. 打 tag

```bash
git tag vX.Y.Z
git push origin main vX.Y.Z      # tag 已存在要先删远端同名 tag
```

CI 自动链：Windows 回归测试 → 三平台并行打包 → Publish Release（内置 4/4 资产清单校验）。

## 2. 发完必查

- [ ] CI 绿，且 **「Create GitHub Release」步骤 = success**（构件已自动回收，见第 4 节）。
- [ ] Release 资产齐全（CI 缺一个就直接失败）。
- [ ] 下载页 / R2 对齐：文件名带 `-vX.Y.Z`、体积、**SHA256** 全部更新（海外站可用第 5 节一条命令对账）。
- [ ] **中台 `auth-backend/src/worker.js` 的 `PRODUCT_RELEASES` 登记新版本** —— 不登记，桌面客户端「检测更新」拿到的还是旧版本号，客户下到老包。
- [ ] 商店包：把本版 `paperformatpro.msix` 传进 Partner Center 并提交（商店版本落后于官网 = 商店用户收到旧版，见第 6 节）。

| product | 对应客户端 | 备注 |
|---|---|---|
| `global` | 海外版 | 客户端**不带 product 参数**，中台回退到 `global` 键 → 改 `global` 即可 |
| `MDF-Stu` | 国内学生版 | |
| `MDF-Advisor` | 国内导师版 | |

🔴 带**未知** product 时中台**故意不回退** global —— 否则国内版会拿到海外版本号，误报「发现新版本」。

## 4. artifact 存储（500MB 配额）—— 已自动化

- 打包件 `retention-days: 1`（三个仓都有）。
- `release` job 末尾有 **「Recycle artifacts」** 步骤：Release 资产挂好后**当场删掉本次 run 的构件**（`if: always()`，发布失败也不留垃圾）。
- 🔴 构件只是「跨 job 传包」的中转；**Release 资产不占 Actions 的 500MB 配额**，真正占配额的是这些中转件。
- 超配额的后果不是"数字难看"，而是 `upload-artifact` 直接报
  `Failed to CreateArtifact: Artifact storage quota has been hit` → **整个 Release 发不出来**。
- 清历史存量：GitHub → Actions → Artifacts → 删；或用 fine-grained PAT（只需 `Actions: Read and write`）调
  `DELETE /repos/{owner}/{repo}/actions/artifacts/{id}`。
  ⚠️ GitHub 用量数字有 **6–12 小时**延迟，删完别盯着看。

## 5. 站点文案对账（海外站 paperformatpro）

```bash
python tools/audit_copy.py --engine <引擎仓路径> --artifacts <产物目录>
```

检查项：规范白名单 / 规范覆盖 / 功能声明是否真存在 / 版本一致 / R2 链接版本 / 公告条一致 / 下载口径一致 / 购买按钮置灰 / SHA256 表。

- 事实快照：`tools/build_facts.json`。**改引擎后必须刷新**：
  `python tools/audit_copy.py --refresh-facts --engine <引擎仓路径>`
- 🔴 **不只是「改规范」要刷新 —— 每次版本号变了都要刷新**。快照里存着 `version`，
  站点下载页改成新版本后，CI 会立刻报「版本一致」「下载链接版本」两项红
  （2026-11-16 发 2.3.123 时忘了刷，老板收到 audit-copy 失败邮件）。
  发版顺序插一条：**改完 download.html → 刷 build_facts.json → 一起提交**。
- 本地改了别的页面还没提交时，`audit_copy.py` 扫的是**工作区**，会和 CI 结果不一致。
  想复现 CI：`git archive HEAD | tar -x -C <临时目录>`，把刷新后的快照拷进去再跑。
- CI：`.github/workflows/audit-copy.yml`，push/PR 自动跑，红了 = 文案与代码不同步。
- 🔴 规范名以 `src/engine/specs.py` 的 `SPEC_ORDER` / `SPEC_DISPLAY` 为**唯一事实源**：
  海外版**没有** Chicago / Harvard，**也没有**批量/整组处理功能。

## 6. 商店包（MSIX，微软商店上架用）

Release 里第 **7** 个资产 `paperformatpro.msix`（`build.yml` 的 windows job 里打，`Asset check 7/7` 校验）。
探路流水线见 `.github/workflows/msix.yml`（`MSIX probe`，只在 push 改打包脚本或手动触发时跑）。

- **不进 R2、不进官网下载页**。官网安装走 `zip`/`setup.exe`，商店安装走 Store；msix **未签名**，
  客户双击装不上（Windows 要求受信任签名），摆到下载页只会造成「下了装不上」的投诉。
- 商店上传要**未签名**包（微软在收件时自己签），所以发版流水线里**不签名、不碰证书**。
  要本机验证安装才自签，只发生在 `msix.yml`（自签证书只进 runner 的 TrustedPeople，绝不对外）。
- 🔴 **Identity 三条必须与 Partner Center「产品标识」逐字符一致**：
  `Identity/@Name`、`Identity/@Publisher`、`Properties/PublisherDisplayName`。
  唯一事实源 = `tools/msix/products.json`，别在别处抄。

  | 海外版 PaperFormat Pro | `Reedskill.PaperFormatPro` | `Reedskill.PaperFormatPro_v279h4yy6sm7g` | `paperformatpro.exe` |

## 8. 安装包上传 R2（每版必做，且顺序不能反）

**顺序铁律：R2 先有文件 → 才 push 站点。** Pages 是 push 即部署，先推就会让线上挂出
新版本号而 R2 上还是旧包，客户点下去 404。同理，上传完成前别推站点仓。

**18 个对象**（每产品 6 个 × 3 产品）：`windows.zip` / `setup.zip` / `macos.dmg` /
`macos.zip` / `linux.AppImage` / `linux.deb`，前缀两层 `downloads/v<版本号>/`。
**不上 R2 的**：裸 `setup.exe`（被包成 `setup.zip` 才上，因为浏览器与 Defender 会拦裸 exe）、
`*.msix`（商店包，未签名双击装不上）。

**🔴 本机下行只有 0.1~0.3 MB/min**（走代理），370 MB 要十几个小时，所以**不能**「下载 → 再上传」。
`wrangler r2 object put` 只吃本地文件、不接受 URL。正解是发一个临时 Worker 在 Cloudflare
网络内部搬：`fetch(github) → env.BUCKET.put(key, res.body)`，15 个包 2 分钟内搬完。
现成脚本在 `D:\AgentSpace\_smoke\r2mirror\`（worker.js + wrangler.toml）与
`_smoke/mirror_to_r2.py`、`_smoke/gen_manifest.py`、`_smoke/check_r2_18.py`。

- 🔴 **workers.dev 在国内是不可用的**：`*.workers.dev` 解析到黑洞地址
  （实测 128.242.240.61 / 2001::2d72:bee，直连 21 秒超时、走代理 CONNECT 502）。
  必须给 Worker 挂自有域名（`[[routes]] custom_domain = true`），wrangler 会自动建
  DNS 记录和证书。当前用过的：`r2mirror.reedskill.com`。
- 🔴 **Release 资产名不带版本号**（`MDF-Stu-linux.deb`），版本号是我们拼 R2 名时才加的；
  从 R2 名反推源文件要把版本号摘掉（国内摘完剩 `--`、海外剩 `-.`，都要收一下）。
- 🔴 `wrangler r2 object put` **默认写本地模拟目录**，必须显式加 `--remote`，
  否则命令回 “Upload complete” 而线上仍 404（2026-11-16 踩过）。
- 传完必须逐条对账：`python _smoke/check_r2_18.py` —— HEAD 全部 18 个比**字节数**
  （不看 R2 控制台，它用十进制 MB，会和 MiB 对不上），再抽 4 个真下回来算 SHA256。
