## 二、④ 卡片增长路径 —— 抓到一个真缺陷并已修复（v2.3.52）

### 2.1 现象
首屏（还没点任何按钮）**右卡底部被裁掉 13px**，被裁的正是信任卡/商业区那几行——
用户看着就是"右卡内容被遮挡"。老板 2026-10-04 报的"右卡没变高"里头，
有一半是这个首屏缺陷（另一半是导入论文后的增长，机制本身是对的）。

### 2.2 取证（真机 Tk，非猜测）
脚本 `D:\AgentSpace\_smoke\probe_right_card_growth.py` 实测首屏：

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 右卡**自然**请求高度 | 530 | 530 |
| 右卡**实际**高度 | **517**（被裁 13px） | 530 |
| 右卡内容是否被裁 | **是** | 否 |

关键区分：右卡的**自然高度自始至终都是 530**（内容没变），
只是**实际分配到的只有 517** —— 所以不是"内容没长高"，而是"没给它够地方"。

### 2.3 根因（代码链条坐实）
1. `src/ui/app.py` `_auto_wrap._apply`：卡片内标签按最终列宽重排后，调用 `_refresh_card()`。
2. `_refresh_card()` 沿 `master` 链向上找**最近的 `RoundCard`** 并 `refresh()`——**只刷卡片，到此 return**。
3. 但外层 `ScrollArea._relayout` 是把画布 window item 高度**钉死**成 `max(内容自然高, 视口高)` 的快照，
   只有 `refresh_layout()` 被调才会重算。首屏换行重排走的是 `_auto_wrap` 这条路，
   此时 `_schedule_first_layout` 早已跑完，**没人再调 area**。
4. 于是：卡片把画布顶到 530 → area 快照还停在 517 → 外层 grid 行高 517
   → 右卡是 `sticky="new"`（高度全看自然高度）→ 被压掉 13px。

### 2.4 修法
- **`src/ui/app.py` `_auto_wrap._refresh_card`**：不再只刷卡片，改为**同时向上找到 `ScrollArea` 并 `refresh_layout()`**，
  让"换行重排"这条路径也能把外层钉死高度一起收口。
- **`src/ui/app.py` `_relayout_all`**：新增一次**有界收敛**重排——
  判据是"滚动区钉死的高度 < 其内容此刻的自然高度"（欠排就补一次）。
  刻意**不用**"卡片实际高 < 卡片请求高"作判据：那一刻卡片自己的请求高也还是旧值（实测 517 vs 517），
  会误判成"没被裁"而跳过补排（这个坑我栽过一次，已在注释里钉死）。

### 2.5 启动速度复核（新增了一次同步 `update_idletasks`，必须实测）
脚本 `D:\AgentSpace\_smoke\probe_startup_perf.py`，同一台机、同一窗口 1280×800：

| 指标 | v2.3.51（有缺陷） | v2.3.52（修复后） | 结论 |
|------|------------------|------------------|------|
| 启动合计 | 1879.8 ms | 1905.3 ms | **+25ms**，噪声级，无 30s 卡顿 |
| 展开 Advanced | 218 ms | 178 ms | 反而更快 |
| 收起 Advanced | 142 ms | 194 ms | 持平 |

**结论：修这个缺陷不影响启动速度**（收敛重排只在"欠排"时才跑，正常路径不额外跑）。

### 2.6 新增回归测试
- `tests/test_ui_redesign.py::test_first_screen_cards_not_clipped`
  —— 钉死"首屏左右卡实际高度 ≥ 请求高度"，防止退回"要用户点一下/拖一下窗口才恢复"。
- `tests/test_ui_redesign.py::test_import_paper_remeasures_right_card`
  —— 钉死"导入论文后右卡跟着长高 + scrollregion 覆盖新增内容"（此前右卡这条**完全没有用例**，左卡有）。

## 三、①②③⑤ 结论（继承 v2.3.51，均已通过）

### ① i18n 回退审计 —— ✅ 安全
`t(lang, key)` 回退链是 `en 值 → en 默认 → key`，英文模式**永不碰 zh**；
`questionnaire_label/help`、`unit_label`、`ALIGN_LABELS["en"]` 英文下只走英文映射。

### ② 全量中文泄漏复扫 —— ✅ 零中文（英文模式）
运行时全链路实测（`verify_leak_full.py`：13 条 checker finding + report markdown + DOCX 25 段 + fixer en 预览 + Other 规范）：
i18n en 词条无 CJK 且 en ⊇ zh、checker 全维度无 CJK、markdown 无 CJK、DOCX 无 CJK、fixer en 预览无 CJK。
AST 扫 `app/widgets/modal_shell/theme/license/main`：**零处非 docstring 中文硬编码**；唯一中文 string 是 `STRINGS["zh"]` 的正当翻译。
`ai_questionnaire_template.yaml` 纯英文。
> `specs.py` 的中文 `name/notes/order_hint/MARGIN_DIMS` 标签经代码追链确认**均未渲染**（下拉走 `_SPEC_DISPLAY`、报告走 `report._DIM_LABEL`、`target.notes` 只装英文 LaTeX 提示）。

### ③ 语言切换后卡片重排 —— ✅ 安全
`_set_lang` 整窗销毁重建 + `F.rebuild` + `_relayout_all` + `_sync_ui`，并冻结窗口几何防漂移。

### ⑤ 测试套件回归 —— ✅ 190 passed / 0 failed（junit XML 核数）
全量 `pytest tests`：**tests=190 failures=0 errors=0 skipped=0**，含 19 个真机 Tk GUI 用例。
> 附带修好一个**先前存在的失败**：`test_two_cards_equal_width_and_right_does_not_follow_left`
> 在 v2.3.51 上稳定失败（`展开 Advanced 后右栏被拽高：513 -> 530`）。
> 已用"改动前/改动后各跑一次完整文件、失败断言与数字完全相同（513→530, 17<=3）"证明它是**既有缺陷、非新引入**；
> 根因就是 2.3 那个首屏裁切，修好后该用例自然转绿。
